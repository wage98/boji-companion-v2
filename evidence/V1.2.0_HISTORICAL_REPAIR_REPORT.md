## 第 1 项 · 启动体验（卡顿 / 黑屏显示 GitHub 网页 / 长时间转圈）

### 根因
- Service Worker 对页面导航走「网络优先」：每次启动都要等 GitHub Pages 的网络响应，网络慢/被墙 → 长时间转圈；托管侧偶发 404 → 用户直接看到 **GitHub 的网页**（黑屏假象）。
- 首屏渲染依赖 `styles.css` 下载完成，期间无任何反馈；壁纸加载失败兜底长达 8 秒。

### 改动
1. **`sw.js` 全面重写**：页面与静态资源一律改为 **stale-while-revalidate（缓存优先 + 后台更新）**；页面请求缓存未命中时回落到缓存的 `index.html`，再未命中返回自托管 HTML 兜底 Response（不再可能落到 GitHub 的 404 页）；`skipWaiting + clients.claim` 保证新版本立即接管。
2. **`index.html` 内联启动闪屏 `#boot`**：logo + 名称 + 动画进度条 + 提示文案，**不依赖任何外部文件**，HTML 一到就能画出来；看门狗定时器 4.5s（提示「还在加载…」）/ 9s（显示重试按钮 + 「网络似乎不通」），把无限转圈变成明确反馈。
3. **资源预加载**：`<link rel="preload">` styles.css / app.js；`app.js` 改 `defer`，不阻塞首帧。
4. **`boot()` 重构**：关键路径（壁纸/形象/首页/隐藏闪屏/事件绑定）同步完成；`showOnboard`、资源预热等非关键工作放 `requestIdleCallback` 延后执行。
5. **壁纸兜底 8s → 3.5s**，且图片 `decode()` 成功后才替换背景，避免半渲染闪烁。
6. **附赠彻底离线方案**：新增 `tools/build-offline.js` → `dist/offline.html`（约 1.66MB 单文件，内联全部 CSS/JS、资源转 dataURI、零网络依赖），适合完全断网场景分发。

### 自查结果
- ✅ 攻击自检 Q1–Q4：boot 闪屏与看门狗存在、`defer`/`preload` 就位、SW 注册仍保留。
- ✅ 全仓库 `grep` 无 `github.com` / `githubusercontent` 引用（启动阶段零跳转）。
- ✅ Chrome headless 截图验收：闪屏、壁纸、dock 均正常渲染；`dist/offline.html` 用 `--virtual-time-budget=6000` 截图验收通过。
- ✅ **线上验证**：`curl` 取回线上 `sw.js` 已是 v1.2 缓存优先版本；线上 `app.js` `APP_VERSION='1.2.0'`，http 200。

## 第 2 项 · AI 语音（僵硬 → 生动有情绪；仅主界面生效）

### 改动
1. **本地韵律引擎**：对照 GitHub 语音方案（`andresayac/ssml-builder`、`AACTools/js-tts-wrapper` 等）复核后确认——它们本质都依赖云端 TTS 引擎/Key，会破坏本应用「纯前端、离线可用、数据不出本机」的底线，故**放弃云端方案**，在 Web Speech API 上自建韵律层（W3C 规范本身不支持 SSML）：
   - `VOICE_MOOD`：8 种情绪（开心/兴奋/关心/难过/困倦/生气/惊讶/平静）各自独立的语速 rate / 音调 pitch / 音量 vol 基线；
   - `voiceSegments()`：按标点切句模拟 SSML `<prosody>` + `<break>`——`！`提速升调+210ms 停顿、`？`音调 ×1.30、`，`短停 170ms、`…`放慢+340ms 长停，逐句独立参数发声，语调起伏明显；
   - `say()` 按当前桌宠情绪 `STATE.petMood` 自动选语气。
2. **作用域硬约束**：`voiceOnHome()` 判定仅桌宠主界面发声；`goModule` / `openAssistant` / `closePanel` / 视频弹层开关统一调用 `voiceSync()`——**离开主界面立即 `stopVoice()` 取消全部待播队列并释放；回到主界面自动恢复 pending 文案**；`visibilitychange` 页面隐藏同样暂停、可见恢复；关闭语音开关即 `stopVoice('off')`。
3. 不支持语音的浏览器（如部分 iOS 环境）在开启入口处直接明确拒绝，不假装可用。

### 自查结果
- ✅ 攻击自检 V1–V6：8 情绪参数齐全、标点切句输出多段且参数不同、`voiceSync` 在 `goModule/closePanel` 均被调用、离开主界面 `VOICE.speaking=false` 且队列清空、关闭开关即停、不支持环境开启被拒。
- ✅ jsdom 无 `speechSynthesis`，已用 stub 验证完整调用链。

## 第 3 项 · 训练动作视频（精确定位变体 + 无跳转内嵌播放）

### 定位精度（先修数据）
- 旧实现 27 个动作共用卓叔合集 `BV1FY4y1y7Vh` + 时间戳（本质是「合集定位」，不是「具体动作定位」，且含卧推椅版本的会混入）。
- 现改为 **`blink(BVID, 真实视频标题)`：每个动作一条独立视频直链**。全站实测：72 个动作视频入口、52 个唯一视频、科普 10 条，合计 62 个唯一 BVID；`vid()` 残留 0、旧合集 BV 残留 0。
- 变体精确匹配：B 站搜索按「标题必须含该动作核心名词 + 教学信号」筛选，含变体词（如「地板」「无椅」「坐姿」）；自动打分首跑 18/19，两例错配（地板飞鸟→肩部反飞鸟视频、集中弯举→泛二头视频）**人工指定更正**（`BV1TjEEzFEyY 地板哑铃飞鸟`、`BV1x6ChBBExH 哑铃集中弯举`），`A_坐姿肩推` 用 anyMust 双词（肩推/推肩）补中。
- **逐条活性验证**：19 条重配视频全部 GET 视频页，均 http 200 且页面无「视频去哪了呢」（B 站死链标志）→ 0 死链。核对表在 `docs/视频来源核对.md`。

### 无跳转方案（后修播放）
- **实测结论**：`player.bilibili.com/player.html?bvid=...` **无 `X-Frame-Options` / `frame-ancestors` 限制**，可以合法 iframe 内嵌 → **App 内直接播放，全程不跳出**。
- `openVideo(url,label)`：应用内视频弹层（16:9 舞台 + 标题 + 关闭），关闭即 `iframe` 销毁并释放资源；`CLOSERS` 接入 `video-pop`（返回键/遮罩点击同样清理）。
- **为什么不做批量下载到本地**（如实说明）：① B 站视频有版权，批量抓取存储/再分发不合规；② 无公开下载 API，高清档需登录态，纯前端 PWA 无法稳定实现；③ 38+ 视频预计数百 MB，超出 GitHub Pages 与用户手机合理体积。**降级方案两条**：弹层内置「📁 本地视频」——用户自存视频可选本机文件直接播放；以及「原站 ↗」直达链接兜底。
- 抖音：无公开嵌入播放器且强制跳转登录，评估后不采用。

### 自查结果
- ✅ 攻击自检 W1–W4：iframe 注入与关闭清理、BV 提取正则、无 `window.open` 跳转残留、62 个唯一 BV 无重复合集。
- ✅ `node --check` 语法通过；线上 `app.js` 已确认含 `openVideo` 且旧合集 BV 为 0。

## 第 5 项 · 照片桌宠（模糊 + 异常表情）

### 根因
- **模糊**：`photoPetSVG` 输出的 SVG 只有 `viewBox` 没有 `width/height`，栅格化时按引擎默认尺寸绘制再拉伸 → 糊；叠加照片压缩参数过狠（256px / 质量 0.72）。
- **异常表情**：旧实现把卡通眼睛+卡通嘴直接叠印在真实照片的五官上，两层五官错位 → 表情诡异。

### 改动
1. SVG 补显式 `width="240" height="240"`；照片上传压缩改为 **512px / 质量 0.9**，canvas `imageSmoothingQuality='high'` + `img.decode()` 后再换图。
2. **默认「保留原图五官」**：不再叠加卡通眼嘴，仅保留极淡腮红 + 蝴蝶结 + 睡眠遮眼等装饰层；「卡通叠加」改为可选开关（开启后才是自绘五官）。
3. **取景微调**：`photoFit()`（缩放 z/水平 dx/垂直 dy，带夹取与脏值兜底）+ 设置页滑杆实时预览 + 一键重置；圆形头像裁切 `preserveAspectRatio="xMidYMid slice"` 保证比例协调、边缘干净。
4. 脏数据防护：`petPhotoFit` 反序列化时 NaN/字符串/null 一律回落默认，`petPhotoFx` 校验合法值。

### 自查结果
- ✅ 攻击自检 Y1–Y6：SVG 带显式宽高、默认不叠卡通五官、开启开关才出现、z=1.8 → image 宽 172.8（数学断言）、脏值回落不崩、上传走 512/0.9。
- ✅ Chrome headless 截图肉眼验收：边缘清晰、五官为照片原生气、比例正常。
